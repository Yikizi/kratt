## Defense-risk analysis
### Probable questions
- What is the single main contribution: a working Estonian wake-word, an evaluation methodology, an integration pattern, or an agentic-engineering position paper?
- If no current single model passes the prefix/confusable test, what does this thesis actually deliver as a working system?
- How can consensus 0.8 FAPH and checkpoint 0.00 FAPH be reconciled with 21–45% real-speaker recall — is the system in any sense usable?
- Why should we accept the three-audit-ring pattern as a research contribution rather than as an internal engineering story?

- How are the four FAPH variants comparable, given that you correctly note the literature does not agree on counting rules?
- Friend1 (N=145) is one speaker; can a single speaker carry the unseen-speaker generalization claim?

### Weak answers if unfixed
- Ambiguity on the main contribution will undercut the audit-ring story — the strongest defendable piece — and let the committee redefine the thesis around a weaker piece.
- Treating user testing as 'will happen' rather than as a scope decision (done / pilot only / explicitly out of scope) turns a limitation into a perceived incompleteness.
- Citing checkpoint-FAPH 0.00 without leading with the shortcut critique invites cross-examination on shortcut learning.
- Defending the agentic-engineering framing as a parallel contribution risks a redirect into 'is this an Estonian wake-word thesis or a thesis on LLM-assisted research'.

### Suggested preparation
- Pin one sentence: 'This thesis contributes a methodologically corrected, three-round audit pattern for evaluating low-resource wake-word detection, demonstrated on Estonian "Kuule Kratt".' Treat the wake-word model and the ESP32-HA integration as supporting evidence, not parallel contributions.
- Decide and rehearse the user-testing scope statement before defense: completed pilot of N participants, or explicitly declared as pilot/future work with named reasons.
- Prepare a one-line narrative for each audit ring: 'expected metric → observed metric → real-world failure → metric vector expansion → unresolved residual'.
- Prepare a claim-to-evidence map: every numeric claim (0.8 FAPH, sub-1 FAPH, prefix-FPR 82%) maps to one specific table or benchmark file with thresholds, sample sizes, and CIs.
- Tie the agentic-engineering paragraph to the evidence-cost argument: agentic dev reduces tooling cost but does not reduce evidence cost, which is precisely why user testing still needs humans. Land it as a closing observation, not a parallel claim.
